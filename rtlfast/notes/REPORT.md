## 第 3 次运行（2026-10-19 06:02 UTC 起）

### 结论
- 目前最好的 verdict：d93d1d3（results/20261019-d93d1d3），门限 PASS，覆盖率 1.0 / 1.0，rocket 5.406 倍（42.1k 到 227.4k 周期每秒），smallboom 2.969 倍（13.5k 到 40.2k），均为 significance faster。rocket 已进入任务书里 GSIM 的 5.3 到 5.7 倍范围。本次开始时是 rocket 4.98 倍、smallboom 2.20 倍（f792bc5）。

### 测量
- smallboom 剖析（47e82bb）：每周期运行 725 个分区，其中 308 个有输出变化；按静态节点数计每周期 12.5 万个节点的工作中，6.9 万发生在没有任何输出变化的运行里。语句级门控的理想工作量是每周期 8.0 万个节点。64% 的工作量在每周期运行 80% 以上的分区里。
- callgrind（smallboom，fb45a89）：每周期约 9.9 万条指令，其中捆绑的小分区 4.25 万，大分区 5.13 万，_eval_body__nba 4.8k。
- 造成"白跑"的输入：自由计数器（mcycle 之类，每周期都变），取指索引（f4_idx、s1_idx），流水线寄存器 r_uop_*；rocket 的 CSR 读多路选择器每周期都因 mcycle 变化而重算。这些在分区粒度上无法避免。
- 代码组成（smallboom，-Os，一个文件的反汇编按源码行归类）：变化位更新约 18%，标记和标志约 13%，其余是逻辑和存储。分区代码共约 1.7 MB，超过每核 1 MB 的 L2。
- LargeBoom：4005 个分区，每周期运行 1463 个（37%），每周期 33.3 万个节点的工作量里 18.8 万发生在没有输出变化的运行里；最大的单条语句（LSU）有 13143 个节点、963 个输出。
- 构建时间：不用 ccache 时，oracle 的 harness.cpp 编译本身最长（rocket 47 s，smallboom 155 s，因为有 2.4 万个探针），smallboom DUT 的 make 墙钟时间就等于这个文件的编译时间，所以继续缩短生成代码的编译时间在门限的 make 时间里体现不出来。
- test_regress（d93d1d3，含捆绑、模块临时变量和 optSize）：先在 821 个 vlt 测试上，479 个通过；又在另外 2265 个测试上，829 个通过。没有结果错误。失败都是预期的拒绝、编译日志金样、缺少 verilator_bin_dbg、统计计数检查（BinToOneHot、MergeCond、Subst）、t_prof 的函数名和 cmake；14 个 VCD 金样失败在原版上同样失败，而且它们生成的 VCD 文件与原版完全相同。

### 负面结果
- 语句裂变：把 200 节点以上的 if 语句按分支拆成单独的带守卫语句，再加上按守卫的确定写分析：smallboom 从约 3.0 万掉到约 2.2 万周期每秒（每周期分区运行从 725 增加到 870，静态工作量不变），rocket 不变。只拆 2000 节点以上的语句：smallboom 和 LargeBoom 都没有收益。补丁存于 journal 的 wip/。

- 按位拆分（GSIM 的位级优化）：只读部分位的（输入，分区）对在 rocket 只有 1112/17509，smallboom 1606/45108，不做。
- 全部语句都是 if (c) 的"守卫分区"在调用前检查条件：rocket 只有 36 个，smallboom 47 个，不做。
- 捆绑参数 300/1600、800/3200，分区大小 400 或 1600，亲和最小尺寸 25 或 100：都不比 150/800、800、50 好。
